Key DSA Takeaway:

  • Binary Heaps excel at $O(1)$ maximum inspection and $O(\log N)$ updates, but because a heap is only a partial order, finding the exact rank of an arbitrary user requires an exhaustive $O(N)$ traversal.
  • Augmented Balanced Search Trees (Order Statistic Trees) maintain subtree sizes in each node. This enables both $O(\log N)$ updates and $O(\log N)$ rank queries, eliminating the $O(N)$ rank query bottleneck completely.

Data Structures & Algorithms (DSA) Concepts Explained

1. Why Heaps Alone Are Insufficient for Leaderboards

A Binary Max-Heap only guarantees that parent >= children. It does not enforce order between siblings. Consequently, retrieving the exact rank of a user or finding who is at rank #50 requires scanning or sorting $O(N)$ elements, which is unacceptable under repeated updates.

2. Subtree Size Augmentation in Balanced Trees

By augmenting each node with subtreeSize = 1 + size(left) + size(right) and maintaining it during AVL rotations in $O(1)$ time, an AVL tree transforms into an Order Statistic Tree. We can compute any player's rank in strictly $O(\log N)$ steps.

3. O(1) Key Lookup via Hash Map Pairing

Pure tree search for user IDs by name would require $O(N)$ or secondary keys. By pairing the tree with a Map<userId, NodePointer>, we locate the user's tree node in $O(1)$, extract them in $O(\log N)$, adjust their score, and re-insert in $O(\log N)$.

4. Deterministic Tie-Breaking Logic

When two players share identical scores, ties are deterministically resolved by comparing their lastUpdated timestamp (earlier score achievements rank higher) followed by their unique userId string, preserving strict total order.
